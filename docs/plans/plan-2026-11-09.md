# Plan — 2026-11-09

## Vision

One workspace, no uploads, verified output.

A free PDF tool for people without an Acrobat license. Drop in any mix of PDFs
and images; every page appears in one grid. Arrange, rotate, delete, sign and
type on pages, then export once. Files never leave the device, and the site
refuses to hand over an output it could not verify.

The gap this fills: existing tools (iLovePDF, Smallpdf, BentoPDF, Stirling-PDF)
are one tool per page, so a merge-reorder-sign job means three round trips.
Research: `docs/research/2026-11-09-summary.md`.

## Principles

1. **Avoid, don't fail.** A feature ships only if it is near-100% reliable. Anything
   lossy or heuristic (PDF to Word, text editing, client OCR, PDF/A) is out.
2. **Verified output.** Every export passes `qpdf --check`, a page-count and
   page-size comparison against the plan, and a re-open in PDF.js before the
   download button appears. A failure shows what failed; no file is offered.
3. **Local, provably.** Phase 1 makes no network request after load. A
   Content-Security-Policy with `connect-src 'self'` enforces it. No analytics
   script, no third-party fonts, no CDN.
4. **Non-destructive.** The user's edits are a list of page references and
   stamps (`ExportPlan`). Originals are never modified; undo is free.
5. **Phone is a first-class layout,** not a shrunken desktop.
6. **Fast.** Static site. The shell loads without any PDF engine; engines load
   on first file. Budget: under 150 KB of JS before the first file is opened.

## Phases

| Phase | Scope |
|---|---|
| 1 | Merge, reorder, rotate, delete, duplicate, insert blank or other pages, extract/split, images to PDF, add or remove a known password, lossless compress, strip metadata, sign and type-on-page (signature, initials, text, date, check/cross marks), installable PWA, offline |
| 2 | True redaction with verification (MuPDF, lazy-loaded), real AcroForm fields, compress to a target size, page numbers and Bates stamps, highlight |
| 3 | Opt-in server jobs on a separate origin: OCR, Office to PDF |
| Never | PDF to Word, text editing, certificate signatures, send-for-signature, PDF/A, XFA forms |

## Architecture

SvelteKit 3 + Svelte 5 runes + TypeScript, `adapter-static`, SPA (`ssr = false`),
deployed to Cloudflare Pages. Contracts live in `src/lib/core/types.ts`.

```
files ──► Engine.openPdf / openImage ──► Source (normalized PDF bytes)
                                            │
            DocStore: Source[] + PageRef[] + Asset[] + undo history
                 │                          │
        Renderer (PDF.js)            Engine.exportPlan
        thumbnails, page view        qpdf assemble ► pdf-lib stamps ► qpdf finalize ► verify
```

- **Engine** (`src/lib/engine/`) runs in a Web Worker.
  - Intake: `qpdf` decrypts and rewrites every input, which also repairs damaged
    cross-reference tables. If qpdf reports errors the file is rejected as unreadable;
    warnings become `Source.notes`.
  - Assemble: one `qpdf --empty --pages … --` call builds the page order, with
    `--rotate` for user rotation.
  - Stamps: only when the plan has stamps, `@cantoo/pdf-lib` opens the assembled
    file and draws images, text (embedded, subset font) and vector marks, honoring
    page rotation and CropBox.
  - Finalize: qpdf applies object streams and stream recompression (`compress`),
    AES-256 encryption (`password`), and metadata removal.
  - Verify: see principle 2.
- **Renderer** (`src/lib/render/`) wraps PDF.js: worker-based, lazy, cancelable,
  bitmap cache with a memory cap, pixel cap for iOS (16.7 MP per canvas).
- **DocStore** (`src/lib/doc/`) is framework-free TypeScript: state, commands,
  undo/redo. Svelte components subscribe through a thin runes adapter.
- **Workspace** (`src/lib/workspace/`) is the page grid and its actions.
- **Editor** (`src/lib/editor/`) is the single-page view for placing stamps.
- **UI kit** (`src/lib/ui/`) holds tokens and shared components. See `DESIGN.md`.

## Testing

- Vitest unit tests for engine, store and renderer logic. The engine suite runs
  in Node against `tests/corpus/` (generated and collected PDFs: encrypted,
  rotated pages, CropBox offset, damaged xref, linearized, large scans, forms).
  System `qpdf` (if installed) may be used as an independent oracle.
- Playwright end-to-end tests on desktop and phone viewports, including one that
  fails if any request leaves the origin.
- CI: GitHub Actions on the box's self-hosted runner: check, unit, build, e2e.
