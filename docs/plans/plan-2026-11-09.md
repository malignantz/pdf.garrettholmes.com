# Plan — 2026-11-09

## Vision

One workspace, no uploads, verified output.

A free PDF tool for people without an Acrobat license. Drop in any mix of PDFs
and images; every page appears in one grid. Arrange, rotate, delete, sign and
type on pages, then export once. Files never leave the device, and the site
refuses to hand over an output it could not verify.

The gap this fills: existing tools (iLovePDF, Smallpdf, BentoPDF, Stirling-PDF)
are one tool per page, so a merge-reorder-sign job means three round trips.
Research: `docs/research/2026-11-09-summary.md`.

## Principles

1. **Avoid, don't fail.** A feature ships only if it is near-100% reliable. Anything
   lossy or heuristic (PDF to Word, text editing, client OCR, PDF/A) is out.
2. **Verified output.** Every export passes `qpdf --check`, a page-count and
   page-size comparison against the plan, and a re-open in PDF.js before the
   download button appears. A failure shows what failed; no file is offered.
3. **Local, provably.** Phase 1 makes no network request after load. A
   Content-Security-Policy with `connect-src 'self'` enforces it. No analytics
   script, no third-party fonts, no CDN.
4. **Non-destructive.** The user's edits are a list of page references and
   stamps (`ExportPlan`). Originals are never modified; undo is free.
5. **Phone is a first-class layout,** not a shrunken desktop.
6. **Fast.** Static site. The shell loads without any PDF engine; engines load
   on first file. Budget: under 150 KB of JS before the first file is opened.

## Phases

| Phase | Scope |
|---|---|
| 1 | Merge, reorder, rotate, delete, duplicate, insert blank or other pages, extract/split, images to PDF, add or remove a known password, lossless compress, strip metadata, sign and type-on-page (signature, initials, text, date, check/cross marks), installable PWA, offline |
| 2 | True redaction with verification (MuPDF, lazy-loaded), real AcroForm fields, compress to a target size, page numbers and Bates stamps, highlight |
| 3 | Opt-in server jobs on a separate origin: OCR, Office to PDF |
| Never | PDF to Word, text editing, certificate signatures, send-for-signature, PDF/A, XFA forms |

## Architecture

SvelteKit 3 + Svelte 5 runes + TypeScript, `adapter-static`, SPA (`ssr = false`),
deployed as a Cloudflare Worker with static assets (`wrangler.jsonc`). Contracts live in `src/lib/core/types.ts`.

```
files ──► Engine.openPdf / openImage ──► Source (normalized PDF bytes)
                                            │
            DocStore: Source[] + PageRef[] + Asset[] + undo history
                 │                          │
        Renderer (PDF.js)            Engine.exportPlan
        thumbnails, page view        qpdf assemble ► pdf-lib stamps ► qpdf finalize ► verify
```

- **Engine** (`src/lib/engine/`) runs in a Web Worker.
  - Intake: `qpdf` decrypts and rewrites every input, which also repairs damaged
    cross-reference tables. If qpdf reports errors the file is rejected as unreadable;
    warnings become `Source.notes`.
  - Assemble: one `qpdf --empty --pages … --` call builds the page order, with
    `--rotate` for user rotation.
  - Stamps: only when the plan has stamps, `@cantoo/pdf-lib` opens the assembled
    file and draws images, text (embedded, subset font) and vector marks, honoring
    page rotation and CropBox.
  - Finalize: qpdf applies object streams and stream recompression (`compress`),
    AES-256 encryption (`password`), and metadata removal.
  - Verify: see principle 2.
- **Renderer** (`src/lib/render/`) wraps PDF.js: worker-based, lazy, cancelable,
  bitmap cache with a memory cap, pixel cap for iOS (16.7 MP per canvas).
- **DocStore** (`src/lib/doc/`) is framework-free TypeScript: state, commands,
  undo/redo. Svelte components subscribe through a thin runes adapter.
- **Workspace** (`src/lib/workspace/`) is the page grid and its actions.
- **Editor** (`src/lib/editor/`) is the single-page view for placing stamps.
- **UI kit** (`src/lib/ui/`) holds tokens and shared components. See `DESIGN.md`.

  in Node against `tests/corpus/` (generated and collected PDFs: encrypted,
  rotated pages, CropBox offset, damaged xref, linearized, large scans, forms).
  System `qpdf` (if installed) may be used as an independent oracle.

  fails if any request leaves the origin.
- CI: GitHub Actions on the box's self-hosted runner: check, unit, build, e2e.

## Phase 2 design (2026-11-10)

Contracts for all of this are in `src/lib/core/types.ts`. MuPDF.js (`mupdf`, AGPL)
is the second engine: loaded by dynamic `import()` in the engine worker only when
a plan needs it (form fields, redaction, target size). It is never in the entry bundle.

Export pipeline, in order. Stages in brackets run only when the plan asks for them:

```
qpdf assemble ► [forms: set values, flatten] ► [redact] ► [stamps + numbering]
            ► [shrink images ► ] qpdf finalize ► verify
```

| Feature | How | Check that must pass (else no file) | Left out on purpose |
|---|---|---|---|
| Highlight | `highlight` stamp drawn with Multiply blend by pdf-lib: a box (slightly rounded rectangle), or with `pen` (2026-11-10) a freehand stroke, `PenStroke` = points in stamp space plus a width as a fraction of page height, drawn as one stroked path with round caps and joins; `box` then covers the stroke and moves with its points. The editor's Pen (default) simplifies strokes (RDP) and stores nearly straight ones as a two-point line snapped to level/upright within 4° | usual checks; pen points must lie inside `box` | snapping to text lines (heuristic); resizing a pen stroke |
| Page numbers, Bates | `ExportOptions.numbering`; text in the stamp font, 0.5 in from the edge, upright on rotated pages | `numbering`: each label is read back from its page | per-page overrides, custom fonts |
| Redaction | `redact` stamp; MuPDF redaction annotations applied (text glyphs, image pixels, line art, links and annotations under the box). Forms are flattened first and metadata is stripped | `redaction`: two engines (MuPDF, PDF.js) find no text under any box, the box renders solid black; checked right after the stage and again on the final file (own stamps over a box are allowed) | search-and-redact, whole-page raster fallback |
| Form filling | `Engine.formFields` lists text, checkbox, radio and choice fields; answers live per source in `FormValues`; MuPDF writes values and appearances; optional flatten | `forms`: every answer reads back from the final file (or, flattened, no fields remain and text answers are on the page) | XFA, signature fields, fields computed by form scripts (shown read-only), rich text, comb layout fidelity beyond MuPDF's |
| Target size | `ExportOptions.targetBytes`; ladder of image resolution caps and JPEG quality, stops at the first step that fits; only plain 8-bit grey/RGB images are re-encoded | `visual`: each page rendered before and after must match within a tolerance; `target-size` | re-encoding 1-bit scans, CMYK, masked or indexed images; font subsetting |

Rules that follow from "avoid, don't fail":

- A redaction box that cannot be verified refuses the export; there is no "cover only" fallback.
- If the size target cannot be reached, the smallest verified file is offered with the real size.
- A source page duplicated in the grid shares its form answers with its copies (answers belong to the source).
- Form answers in thumbnails and the page view are a PDF.js preview; the exported appearance is MuPDF's.

Streams and paths are as in the ownership table. Engine work is split by module
(`mupdf.ts` loader, `forms.ts`, `redact.ts`, `shrink.ts`, `numbering.ts`), each with
its own test file, so streams do not edit the same code.

## Engineering backlog (phase 1 leftovers go here, not in a to-do file)

- Web Share Target and `file_handlers` for "Open with".
- OPFS spill for files over ~150 MB.
- Split into several files (zip) in one export.
- Phase 2 leftovers: highlight that snaps to text lines; search-and-redact; whole-page raster redaction as a fallback; shrinking 1-bit and CMYK images.
- Form filling: the editor lays text upright on the page as displayed. A widget whose text runs at an angle to the page (rotated page with /MK /R not matching) shows its answer upright while typing; the page shows it as the file draws it. Fix needs the widget's text rotation in `FormWidget` (contract change).
- Phase 2 known limits (built 2026-11-10): redaction does not search bookmarks, named destinations or scripts for the hidden text; form answers are Latin-only and must fit their box; calculated fields are not recalculated (export warns); a field split across pages becomes one field per page in an unflattened export when pages are copied (two sources, or a repeated page; a single source with a form is edited in place and keeps its fields); list boxes and multi-select are read-only; phone keyboard handling is tested in emulation only.
- Redaction known limits (survey fix round 1, 2026-11-11): drawings, annotations and smaller gradients touching a box go whole (the export warns for drawings; a gradient or pattern covering over a quarter of the page is refused); letters only partly under a box go whole (warned); MuPDF's content rewrite can still change a page slightly outside the box (one survey file: sub-half-point text shifts and a lost background tone), and moves of half a point or more are refused; form flattening (forced by redaction) can drop field values or show other widget states (forms.ts, e.g. NeedAppearances with non-Latin values); PDF 2.0 brotli streams cannot be checked (MuPDF build).
- MuPDF wasm traps: a trap becomes a refusal and the instance is replaced (Node: fresh module copy; browser: the worker is replaced and unanswered calls re-sent). Not measured in a real browser yet; an e2e test that forces a trap in the worker would close that.
- Survey fix round 1 (intake/assemble/forms, 2026-11-11) known limits: (1) source damage that stops `qpdf --check` (corrupt JPEG data) is refused at export, not at open: an intake `--check` would catch it but costs 3-20 s on large files; (2) files whose xref is broken *and* which are encrypted (even owner-only) are refused, because the pdf-lib repair cannot decrypt; (3) hybrid XFA+AcroForm forms are not offered for filling, although both assemble paths now drop the XFA part; enabling them needs a survey of the AcroForm side's scripts and appearances first; (4) MuPDF lays out text in widgets on rotated pages without /MK /R off the box (refused as "does not fit"); (5) no rendered before/after comparison inside the engine: ~0.1-0.5 s per typical file with MuPDF loaded, but 15+ s for one large map page, so it would need a time budget.
- Stamps known limits (survey 2026-11-11): a page whose content stream is corrupt (undecodable Flate) or ends inside a string, array, dictionary or inline image is refused as damaged, since anything appended would be swallowed; wrapping the original content in a Form XObject would isolate it but breaks tagged-PDF structure, so it is not done. Annotations paint above stamps: the export only warns when a visible annotation, push button or opaque field overlaps a stamp. A CropBox that misses the MediaBox follows PDF.js (MediaBox shown); poppler and MuPDF show an empty page there.
- Survey crash fixes (2026-11-11) known limits: redaction on a very large, dense vector page (a 22 MB USGS map sheet, 2842×4149 pt) needs about 2.5 GB in Node; no cheap up-front guard predicts it (memory follows content complexity, not page or pixel size), so it is left to the out-of-memory path ("too large to process on this device"; not measured in a browser); a page whose dictionary itself has a qpdf warning (such as a name with a stray "#") is refused at open, because listing pages accepts only a clean qpdf run.
- One unexplained flaky `npm test` run (9 failures, then 9 clean runs) after the editor-tools merge. If it recurs, capture the log before rerunning.

## Stretch: make a flat form fillable (after phase 2, not started)

Detect blanks locally and deterministically: long underscore runs in text, drawn rules (filtered so table grids and underlines are not taken), small squares as checkboxes, with the nearest label as the field name. Offer them as suggestions the user confirms ("tap a blank to type", then "Make fillable" writes real AcroForm fields, verified like any export). No AI in the browser (no-network rule); AI naming or scanned forms with OCR would be a phase 3 opt-in server job. Rule: measure the detector on 10-20 real office forms first; if it is not near-perfect, pass on the feature.
